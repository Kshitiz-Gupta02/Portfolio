Ambulance Routing via Graph Theory

Modelling a city's road network as a weighted directed graph, and using Dijkstra's algorithm to minimise ambulance response time in the emergency "golden hour."

CourseDOM208 — Operations Research
ToolsDijkstra's Algorithm, Bipartite Matching

Problem

In emergency medical services, the first hour after a critical incident — the "golden hour" — is often the difference between life and death, and a meaningful chunk of it is consumed simply by ambulance travel. Most real-world dispatch still leans on driver intuition rather than mathematical routing. This project treats ambulance dispatch as an Operations Research problem and solves it with Graph Theory.

Model Design

The road network is represented as a weighted, directed graph — junctions and locations as nodes, travel time in minutes as edge weight. It's directed because some roads (especially near hospitals) are one-way, so the fastest path from H to a patient isn't always the same road in reverse. The objective function minimises total response time T(Pk) = d(H, Pk) + t_load + d(Pk, H) for every patient Pk.

Algorithms Used

Dijkstra's Algorithm finds the minimum-weight path between the hospital and a patient node — run twice per trip, once onward and once for the return leg, since one-way roads mean the fastest path isn't always symmetric.

Bipartite Matching extends the model to multiple simultaneous calls: ambulances on one side, patients on the other, with edge weight equal to the response time if that ambulance is sent to that patient. A minimum-weight matching keeps the combined response time low across all calls, not just one at a time.

Sample Network

H = hospital base station, J1/J2 = road junctions, P1–P3 = patient call locations. Edge weights are travel time in minutes. For a call from P2, Dijkstra's algorithm compares H→J1→P2 (4+5=9 min) against H→J2→P2 (6+4=10 min) and picks the faster route.

Before this model, the habitual route ran via J2 out of driver familiarity rather than actual speed. This looks small for one trip, but scaled across a full day of emergency calls, the cumulative time saved becomes significant — and in emergency medicine, every minute matters.

KPI Framework

Since the goal was a performance management model, not just a routing exercise, I proposed 8 KPIs for continuous tracking: Average Response Time, Average Turnaround Time, Ambulance Utilisation Rate, Coverage Efficiency, Idle Time per Ambulance, Distance Efficiency Ratio, Patient Waiting Time, and Cost per Trip — giving a hospital control room a way to monitor whether the model keeps improving performance once adopted, not just a one-time calculation.

Limitations

The model assumes static travel time (no real-time traffic), fixed node positions (patient locations only known once a call comes in), and doesn't account for ambulance breakdown or unavailability. Future scope includes live GPS/traffic integration, dynamic graph updates for road closures, and extending to a multi-hospital, multi-ambulance network.
